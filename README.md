# Remember me

**给它一个 AI 伴侣，十年后她还记得你妈哪年住的院。**

不是"记住更多"，是"记得住一辈子"。原文一字不改地存，从不生成摘要，零次模型调用，零第三方依赖。

---

> **English TL;DR** — A long-term memory engine for AI companions that stores every user
> utterance **verbatim** and never summarizes. Importance is decided by closed word lists
> and arousal cues (Zeigarnik / body reactions / decision announcements), not by an LLM.
> The abstraction path makes **0 model calls**, so it cannot suffer the "repeated LLM
> summarization degrades memory" failure mode. Retrieval returns a **time-axis cross-section**
> so the model can answer *"what happened that year"* and *"how long did it last"* — questions
> vector search structurally cannot answer. Pure Python stdlib, ~2.3k lines (300 of them are word lists), no GPU,
> no embedding, no network.

---

## 它凭什么不一样

绝大多数记忆方案做的是同一件事：**把对话喂给模型，让它摘要，再存进向量库**。
这条路有三个内生的毛病，不是调参能解决的：

| 毛病 | 后果 |
|---|---|
| 摘要是模型写的 | 模型会把自己的措辞当成你说过的话（记忆漂移） |
| 反复摘要会退化 | 有论文实测：连续更新 10 轮后准确率 100% → 54% |
| 只存语义不存时间 | 答不了"那年"，更答不了"这件事持续了多久" |

本项目的三条硬约束，分别对着这三点：

1. **原文不可改。** 写进去的是用户说的话，读出来的也是。库里的每一句都是某条真实发言的连续子串。
2. **抽象路径上 0 次模型调用。** 判定、聚簇、取关键词全部是封闭词表 + 纯规则。规则会判错，但规则不会漂移。
3. **遗忘改的是形态，不是可达性。** 行业里所有"遗忘"都只是降权、搜不到，字还在。这里是让它在时间轴上真的退化成关键词——**但原文仍然完整躺在磁盘上，一个字节都不删**。

### 「一段的长度」这个信息，只有轴有

这是整个项目最想说的一句话。

```
病    12次   跨 0.3 年   2021-03-16 → 2021-07-04
住处  18次   跨 4.7 年   2021-07-24 → 2026-04-08
```

「老陈的病拖了三个多月」「房子的事她纠结了四年七个月」「那一跤之后她怕了两年」——
向量检索无论怎么调，都给不出这三个句子。因为它们的答案不在任何一条记忆里，**在两条记忆之间的距离里**。

人的记忆就是这样组织的。你记得的不只是"我妈住过院"，还有"那是从三月开始的，拖到了夏天"。

## 安装

纯 Python 标准库，**没有任何依赖**。Python 3.8+。

```bash
git clone https://github.com/<你的用户名>/Remember-me-skill.git
cd Remember-me-skill
python run.py selftest        # 22 条不变量，全绿才算装好
```

作为 Agent Skill 使用时，把整个目录放进你的 skills 目录，**目录名用 `remember-me`**
（WorkBuddy：`~/.workbuddy/skills/remember-me/`；Claude Code：`~/.claude/skills/remember-me/`）。
目录名要和 `SKILL.md` 里的 `name` 一致，钩子的绝对路径也会指向它。

## 装好之后：不用再手动调用

**你不需要每轮都调它。** 挂一个钩子，之后正常聊天就行。

在 `~/.workbuddy/settings.json` 里加一段（`hooks` 的格式和 Claude Code 一致）：

```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "\"<python 绝对路径>\" -S \"<skill 目录>/hooks/remember_hook.py\"",
            "timeout": 20,
            "statusMessage": "记住这句话"
          }
        ]
      }
    ]
  }
}
```

改完**要完全退出 WorkBuddy 再打开**（右键托盘图标退出，或任务管理器结束所有 `WorkBuddy.exe`）。
只关窗口不算——引擎会在启动时对钩子配置做快照，daemon 还活着的话仍用旧配置。

之后会发生三件事：

| 场景 | 它做什么 |
|---|---|
| 你随便说一句（"今天下雨了"、"我妈住院了"） | 存进库，**不占上下文** |
| 你问"你还记得…""上次…""那年…""什么时候…" | 自动把相关记忆贴进上下文，模型于是想起来了 |
| 你说"/clear"或跑代码任务 | 跳过，不入库 |

看不懂它在不在工作？看 `~/.remember-me/hook.log`，每一轮都会留一行：

```
2026-10-27 15:33:01  OK 存=18字 注入=0字 | 今天下雨了路上好堵
2026-10-27 15:33:20  OK 存=14字 注入=1426字 | 你还记得我妈身体怎么样吗
```

没有新行 = 钩子没被触发，多半是没完全退出重开。

三种关法：

- **全局**：从 `settings.json` 删掉 `hooks.UserPromptSubmit` 这一段
- **单个目录**：在该目录下建一个空文件 `.remember-me-disable`（适合放代码项目，免得工作对话混进人生记忆）
- **临时**：环境变量 `REMEMBER_ME_HOOK=off`

> 为什么"存"和"提"要分开：每轮都注入会撑满上下文，而且十句话里有九句（"帮我改个 bug"）跟人生记忆无关。
> 琐事照样入库，只是不主动提。
>
> **`-S` 别省**：钩子每条消息都要新起一个 Python 进程，而 Python 启动时会扫 `site-packages`。
> 本机实测（同一台机器、同一份脚本、P50）：
>
> | | 默认 | 加 `-S` |
> |---|---|---|
> | 直接 exec | 488 ms | **293 ms** |
> | 经 shell | 708 ms | **447 ms** |
>
> 钩子只用标准库，`-S` 跳过 site 完全安全，省 40%。**别用 `-I`** —— 它隐含 `-E`，
> 会忽略 `PYTHONIOENCODING`，中文日志立刻变乱码（实测过）。
>
> **输出的格式是硬要求**：`UserPromptSubmit` 的 stdout 不是裸文本，宿主只认
> `{"hookSpecificOutput": {"hookEventName": "UserPromptSubmit", "additionalContext": "..."}}`。
> 直接 print 一段文字，宿主解析不出来，等于白跑一轮 —— 我第一版就是这么写的。
>
> 换到别的宿主（Claude Code / 其他 Agent 框架）时，把 `hooks/remember_hook.py` 挂到它对应的
> "用户提交前"事件上即可——它就是一个读 stdin JSON、往 stdout 打印文本的普通进程。

## 用法

```bash
python run.py init                              # 建库（默认 ~/.remember-me）
python run.py add "我妈住院了"                    # 存一句原话
python run.py add "今天下雨了" --date 2024-03-05  # 补历史
python run.py ingest chat.tsv                   # 批量：日期<TAB>原话
python run.py recall "我妈身体怎么样"             # 取横截面（贴进上下文）
python run.py axis                              # 看人生轴
python run.py milestone                         # 看刻度（一辈子最重的那几十句）
python run.py stats                             # 看统计
python run.py rejudge                           # 判定器升级后重算全库（先 --dry-run 看一眼）
```

### 接进任何模型（三步）

```python
from engine.store import Store
from engine import axis

st = Store("~/.remember-me")

for line in user_turns:                     # ① 每轮都存，不调模型
    st.add(line)

block = axis.render(st.load(), question, idx=st.index())   # ② 取这次要的那几句
messages = [                                                 # ③ 贴进上下文
    {"role": "system", "content": SYSTEM_PROMPT + "\n\n" + block},
    *history,
    {"role": "user", "content": question},
]
```

`recall` / `render` 的输出已经是可直接粘贴的格式，带日期、带 ★ 刻度标记、带类别提示
（`（涉及：生死、病、住处）`）。**它不绑定任何模型厂商**——因为它只是一段文本。

## 实测数字

全部可复现：`python bench_scale.py` 会现场造 1 万 / 5 万 / 20 万条语料并计时，不读历史结果。

### 写入与存储

| | 数字 |
|---|---|
| 写入（含 fsync，每 50 条一次） | **P50 0.26ms / P95 0.36ms** |
| 单条开销 | **85 ~ 151 字节**（短句 / 长句） |
| 十年密集陪伴（36.5 万条） | **31 ~ 55 MB** |
| 五十年（182 万条） | **155 ~ 275 MB** |

**这就是敢说"完整的一生"的底气：不是靠压缩，是原文本来就不贵。**
一个 50 年的完整人生对话，比手机里任何一个游戏都小。

### 读取延迟

| 规模 | 冷启动 load | 热启动 load | 召回 P50 | 召回 P95 |
|---|---|---|---|---|
| 1 万条 | 99ms | 10ms | 2.3ms | 3.4ms |
| 5 万条 | 455ms | 47ms | 10.9ms | 16.5ms |
| 20 万条 | 1831ms | **201ms** | **36.3ms** | **123ms** |

三个关键优化（都有实测对照）：
- 写入时定型事件类型，读时不再跑正则 → 冷启动省一半
- pickle 缓存 + `(mtime, size)` 签名 → 热启动 1726ms → 185ms
- 内存倒排索引，只对候选集打分 → 20 万条召回 368ms → 36ms

> 同一台机器两次跑 20 万条，召回 P50 分别是 36ms 和 83ms。**报保守值，别信单次测量。**

### 效果（A/B，真模型答题）

基线 = 只保留最近 40 条（市面上最常见的"滑动窗口"做法），同一批 12 道人工探针题。

| 人设 | 基线 | 记忆轴 |
|---|---|---|
| 19 岁大学生（奶奶阿尔茨海默） | 9.9% | **33.0%** |
| 45 岁小超市老板（父亲肺癌） | 9.0% | **23.7%** |
| 62 岁丧偶教师 | 5.9% | **54.7%** |
| 33 岁离婚程序员 | 8.8% | **32.8%** |
| **均值** | **8.4%** | **36.1%** |

指标是"答案对真值的二元组覆盖率"（ROUGE-2 recall 近似）。**四个人方向完全一致，没有一个人反向。**

62 岁那位另用一套手写锚点评分逐题读过：**26.4% → 96.4%**，编造 0~1 条。

> **必须说清的三个噪声来源**（谁在 README 里藏这个，谁就是在骗你）：
> 1. 那 3125 句语料是同一个模型扮演的六个人，风格有共性，真实用户分布一定更杂，**这个数到真实场景会掉**。
> 2. 同一份 prompt 跑三次得到 78.3% / 76.4% / 89.6%，**单次测量有方差**。
> 3. 我在调判分口径的过程中结论翻过三次（假日历格式比对曾报出 52 条假编造）。**方向可信，绝对值不可信。**

## 已知边界

写在最前面，因为这是我踩过的坑，不是猜的。

**1. 纯叙述型的重要时刻判不出来。**

> 「考完了，最后一道大题没写完，我走出考场的时候腿是软的，我完了」

没有一个事件词。人在最重要的时刻，**反而不说事件名**。
只用词表判重要性，在这批语料上 P=35.5% / R=27.6%，加三轮规则只涨 0.9 个点。

**这就是为什么判定器不负责删任何东西，只负责打刻度。** 它判错的代价是"刻度不准"，不是"记忆丢失"。

**2. 代词会切断实体线。** 「五点二十，他走了」不含人名。靠常驻刻度层兜底，没有真正的指代消解。

**3. 问句和原文用词不一致时会漏。** 问「为什么从加拿大回来」，讲原因那句里没有"加拿大"。
（已加"问法别名表"和"实体首末时间窗"缓解，未根治。）

**4. 高频实体的覆盖不全。** 一个被提了 90 次的人，单次检索只取其中一部分。

**5. 只有中文。** 词表、停用词、委婉语分级全部基于中文。英文需要重建整套词表。

## 它独特在哪

下面五条不是"我们的效果更好"，而是**架构上做不到别的做法**。

| | 具体是什么 | 为什么别的方式给不了 |
|---|---|---|
| **库里没有一句是模型写的** | `Card` 类型里**根本没有 `text` 字段**，关键词全部是原文的连续子串 | 只要允许模型写一句摘要进库，那一句就会在下一轮被当成"用户说过的话"引用。我们是在类型层面堵死的 |
| **抽象路径 0 次模型调用** | 判定、聚簇、取关键词全是封闭词表和正则 | 0 次调用 = 0 退化。反复让 LLM 总结会掉准确率，这条路径不存在 |
| **能答「持续了多久」** | 轴上的两个坐标算出来的 | 答案不在任何一条记忆里，**在两条记忆之间**。向量库存的是点，没有距离 |
| **召回零写入** | `recall` 是纯函数，有断言保证前后字节一致 | 大多数方案在召回时更新权重/计数，于是"你问过什么"悄悄改变了"你是什么" |
| **遗忘只改形态** | 退化到关键词，原文一个字节不删 | 行业里的"遗忘"都是降权、搜不到，字还在。真删又是拿最贵的东西换最便宜的磁盘 |

再加一个数字：**单次注入约 20 句 / 2~4KB，不随库大小增长。** 库里 600 句还是 50 万句，上下文里这一块都一样大。
这就是"上下文长度"这个瓶颈被绕开的方式——不是把库塞进去，是每次只取这次要的那几句。

如果你要找的是"用 LLM 把对话总结一下存起来"的方案，那这个不是。**本项目在全链路上一次模型都不调用，
代价是判得没那么聪明，换来的是十年后它说的还是你当年那句话。**

## 数据来源

关键事件词表不是手编的，来自可核查的公开来源：

- **张明园《生活事件量表》(LES) 48 项 (1987)** — 事件词骨架。五个公开来源交叉核对，条目完全一致。
- **中文死亡委婉语分级表**（维基词典 / 中国新闻网 / 新华网）— A 级直判（去世/病逝/出殡）、B 级需近亲主体（"奶奶走了"是、"同事走了"不是）、C 级不收。
- **SUBTLEX-CH** (Cai & Brysbaert 2010, PLOS ONE) — 仅用于过滤零频次词与关键词排序。
  > 注意：它是**翻译过来的电影字幕**，中频段是"吸血鬼/凶手/陪审团"，而"腰疼""生孩子""领证"频次全是 0。
  > **不能用它来裁生活词**，我试过，会把最该记的词删掉。
- **哈工大 + 百度 + 四川大学停用词表** — 关键词过滤。

感谢上述项目的作者。

## 不做什么

- 不联网、不用 embedding、不用向量库、不用 GPU
- 不调用模型（判定、聚簇、取关键词全部纯规则）
- 不生成摘要、不改写原话
- 不在召回时写入任何东西（检索零写入，有断言保证）
- 没有删除接口。想"忘掉"只能降检索优先级，不能删字节
- **不存密码、密钥、令牌、银行卡号。** 库是明文 `events.jsonl`，方便你 `tail`、`grep`、备份，
  方便到"打开就能读"。别把不该落盘的东西说给它听；说了就写入磁盘了，本引擎没有加密层
